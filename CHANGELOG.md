Three deterministic damage cases (bit flip ⇒ ChecksumFail, zeroed chunk ⇒ Zeroed, another LOB's block ⇒ ForeignLob) reject only the affected row. golden_cli 10/10, golden_lab 12/12 (v1+v2), 117 tests, fuzz clean.
- **M5 part 1 — inline LOBs (LV-068) and explicit refusal of compressed tables (LV-069)**: new golden set `golden-26ai-20261024` (v2: + `T_LOB_BASIC`, `T_LOB_SECURE`, `T_COMPRESS`; 147,661 truth values; `20_export_golden.sql` exports LOB data via `DBMS_LOB.SUBSTR` because `DUMP()` refuses LOBs). `types/lob.rs::LobLocator` decodes the in-row locator measured on 12 real 26ai locators (BasicFile `09`/`05`, SecureFile `48 90`/`40 90`, lengths big-endian, in-row CLOB data is UCS-2 in an AL32UTF8 database); `ColumnType::Clob/Blob` (type# 112/113) decode inline data exactly, out-of-line locators become `Value::LobOutOfLine` → `rejected` with `LOB stored out of line` (never NULL, never empty, never tainting siblings). `odr extract` refuses a `COMPRESS BASIC` table whole (exit 1, LV-069) instead of printing symbol references. Measured: 14/14 inline LOBs byte/text-exact incl. Arabic CLOB, 4/4 out-of-line rejected, 3/3 compressed blocks refused. Red/green ×4; fuzz `types`/`value` 45 s clean; golden_lab 12/12 on v1 and v2, golden_cli 10/10 (`ODR_GOLDEN_V2`), 117 tests.
- **Step g closed (LV-067)**: `lab_values_match_oracle_dump_byte_for_byte` now compares **every one of the 141,613 truth values** of the 26ai golden set — the two indexed-cluster members `T_CL_DEPT`/`T_CL_EMP` are read through `read_cluster` (key columns are `SEGCOL# 1..CLUCOLS`, member columns follow) and the 10,009 texts the export wrote as `ASCIISTR` escapes (`\0633…`, Arabic / Latin-1 / symbols; `\005C` for a backslash, surrogate pairs outside the BMP) are decoded by `unasciistr` and compared as text instead of being skipped. Exact totals asserted (`values_checked + 12 == 141,613`, 15 tables, ≥ 10,009 un-escaped); `lab_end_to_end_dictionary_to_cells` and `lab2_second_version_reads_like_oracle` (11g, 21c) decode the escapes too (10,007 / 10,000). LV-020/LV-021 (cluster key/member row layout) move to ✅ 26ai at **value** level.
- LV-065 torn partial recovery: a `TailMismatch` block now carries a *damage frontier* (`SegmentRows.torn_frontier`, lowest broken slot rounded down to a 512-byte sector, accepted only if the row directory is wholly below it and the rows placed below it are pairwise disjoint) and every `RawRow` its byte `span`. `odr extract` emits rows lying wholly below the frontier, decoding exactly, as **inferred** (`torn block: … (LV-065)`), never verified. ### Fixed
- Fuzz findings: extent maps claiming > 2^26 blocks are refused by the parser; empty quoted column names in bootstrap DDL are rejected.
- SYSTEM detection no longer requires `kcvfhfno == 1` (PDB SYSTEM is file 12); proven by bootstrap$ rows instead (LV-053).
- `LONG` dictionary columns (`COL$.DEFAULT$`) read from the row's last stored column with the exact-length rule (LV-054).
- `tools/gen_charsets.py --check` compares bytes (Windows CI false "stale").
- Fast ADD COLUMN: bit-vector indexes nullable fast-added columns only; set bit ⇒ explicit NULL even when trailing-absent (LV-050).
- `NUMBER` `80 02` (1E-130) decodes instead of being rejected (LV-051).
- ROWDEPENDENCIES `dscn` is 7 bytes on 26ai; width settled per block from the row-packing invariant, never guessed (LV-052).
- `ktbbhict` is one byte (LV-047): 26ai writes 0x1F at 0x25, so the old u16 read rejected ~9.8k real blocks.
- Empty formatted data blocks (`ntab=0,nrow=0,fsbo=14`) are well-formed (LV-048).
- `nrid`/`hrid`/cluster `prev,next` are big-endian on every platform (LV-049) — chained and migrated rows now assemble on little-endian files.
