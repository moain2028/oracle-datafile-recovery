## 4. الاكتشافات الحقيقية (من الملف لا من المصادر)
1. **`0xFE` بترتيب بايت الملف** (LV-009 مدحوض) — كان سيُفشل كل قيمة > 250 بايت. مُصلَح.
2. SYSTEM في 26ai **bigfile**: `rfile# = 1024`، ونص bootstrap$ يكتب `EXTENTS (FILE 1024 BLOCK b)` (LV-042). **المحلّل القادم يجب أن يعامل `FILE 1024` = «الملف الحالي»**.
3. رأس MSSM يدرج extent الأول **بعد** كتلة الرأس؛ ASSM يدرجه كاملاً (LV-043).
4. `kcvfhrdb = 520` في **كل** ملفات الـ PDB (LV-044).
5. OBJ$ في 26ai 37 عموداً (11g: 21) ← المخطط يُقرأ من bootstrap$ حصراً (LV-045).
6. رقم صف ROWID لعضو cluster نسبي إلى قسم `kdbt` الخاص بجدوله (LV-046).
7. `ktbbhict` بايت واحد؛ 26ai يكتب 0x1F في البايت 0x25 — قراءة u16 رفضت ~9.8k كتلة حقيقية (LV-047). مُصلَح.
8. كتلة بيانات مهيأة فارغة (`ntab=0,nrow=0,fsbo=14`) سليمة (LV-048). مُصلَح.

## 5b. عائق CI (Windows) — مُصلَح في PR #19
- كانت وظيفة **windows-latest** تفشل في `Charset tables up to date`: `OUT.read_text()` في بايثون على Windows يفكّ الملف بترميز النظام ويحوّل نهايات الأسطر فيختلف عن النص المولَّد. الإصلاح: مقارنة بايتات (`read_bytes()` مقابل `body.encode("utf-8")`). `.gitattributes` كان أصلاً `eol=lf` فلم يكن هو السبب. تحقّق من اخضرار CI بـ `gh pr checks <n>`.
- **درس CI:** البوابات المحلية لا تبني `fuzz/` (crate مستقل بـ nightly)؛ أي تغيير في API عام (مثل `PieceFormat`) يجب أن يُتبع بـ `cd fuzz && cargo check --bins` قبل الدفع — وإلا تسقط وظيفة `fuzz-smoke` فقط على GitHub (حدث في PR #19 وأُصلح).
- أمر التحقق: `gh pr checks <n>` / `gh run list --branch main --limit 3`.
